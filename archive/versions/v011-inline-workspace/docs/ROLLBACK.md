# 源码副本与回档规则

## 必须遵守

每一批修改（含错误修复）先复制上一版本，再在新副本修改。旧版本封存后不能编辑。Git 提交和标签不代替完整目录副本。

`versions/v001-foundation` 是第一个基线，SEAL.json 记录它的文件列表、字节数和 SHA256。后续版本使用 v002、v003 等递增编号，禁止嵌套复制 versions。

## 下一版本

1. 运行上一版 scripts/check.mjs，核实封存完整性。
2. 把上一版本目录完整复制到新目录，禁止硬链接；不复制 node_modules、构建缓存与旧 SEAL.json。
3. 所有实现和修复在新目录中进行，不编辑旧目录。依赖清单及锁文件必须在版本中保留。
4. 记录本版来源、改动、验证结果、已知限制。检查完成后生成新 SEAL.json 并提交。
5. 每批修复即使很小也新建下一个副本。源码改动以版本目录为准，根目录仅保存项目入口及管理规则。

## 回档

选择上一个封存版本，检查封存哈希，按该版说明安装锁定依赖并构建。旧目录不直接继续开发；恢复开发时复制为新的递增版本。

user-data、browser-profile、captures、安装包和个人 PMGX 位于版本目录之外。回档源码不能删除或覆盖个人藏品。数据库迁移先备份后迁移副本；不兼容时使用对应备份，禁止对唯一副本破坏性降级。

初始基线只包含规格、样例和本地检查脚本，不包含已实现的应用程序。
